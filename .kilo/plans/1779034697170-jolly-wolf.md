## Problem
Spring Boot auto-scans all `*.graphqls` files in `src/main/resources/graphql/` and merges them into a single `TypeDefinitionRegistry`. Types, inputs, enums, and root operation types (`Query`, `Mutation`) are being duplicated across files, causing a `SchemaProblem` at startup.

## Key Structural Differences (MUST be merged/decided)
1. **`Form` type**: `forms.graphqls` has more detailed schema (section/action nesting, version fields)
2. **`ConsultationAnswers` type**: `forms.graphqls` uses `UUID` IDs; `user.graphqls` uses `ID` + string formVersion
3. **`ApiResponse`**: `user.graphqls` uses an `interface`; `forms.graphqls` uses a concrete `type`
4. **`forms.graphqls`** has extra enums not in `user.graphqls`: `HeaderPlacement`, `ActionType`, `MessageType`, `UUID` scalar
5. **`forms.graphqls`** has extra types: `Message`, `FormsListResponse`, `DiagnosticRecordEntry`, `MedicationLongFormEntry`, `MedicationMiniFormEntry`, `ActionListener`, `TableAnswer`, `FormVersion`
6. **`forms.graphqls`** has extra inputs: `DiagnosticRecordEntryInput`, `MedicationLongFormFormEntryInput`, `MedicationMiniFormEntryInput`, `ActionListenerInput`, `TableAnswerInput`

## Strategy
Since `user.graphqls` already contains a superset of Query/Mutation logic including form operations, it should be the **single source of truth**. All form schema types/inputs/enums from `forms.graphqls` must be appended to `user.graphqls`, and `forms.graphqls` must be replaced with only a `extend type Query` / `extend type Mutation` block listing the form operations pointing to the types in `user.graphqls`.

### Steps
1. **Read current `forms.graphqls` fully to understand contribution**
2. **Merge unique form types from `forms.graphqls` into `user.graphqls`**:
   - Add missing enums: `HeaderPlacement`, `ActionType`, `MessageType`
   - Add `scalar UUID` to `user.graphqls` if not already there
   - Merge `Form`, `ConsultationAnswers`, and `ConsultationAnswersInput` with the more detailed `forms.graphqls` versions
   - Add new input types: `ConsultationAnswersInput` (detailed), diagnostic/medication inputs
   - Add new types: `Message`, `FormsListResponse`, `FormVersion`, `DiagnosticRecordEntry`, `MedicationLongFormEntry`, `MedicationMiniFormEntry`, `ActionListener`, `TableAnswer`
   - Keep `ApiResponse` as `interface` (consistent with `user.graphqls` pattern); drop `forms.graphqls`' concrete `type ApiResponse`
3. **Replace `forms.graphqls`** with only `extend type Query` and `extend type Mutation` blocks using `extend` keyword (so no duplicate root type definitions). Ensure Query/Mutation return types are properly defined in `user.graphqls` first.
4. **Verify no duplicate types remain** after merge.
5. **Run `mvn compile` or equivalent** to verify schema compiles cleanly.
